# Notes — New Graduate

## What changed

1. **Summary tightened.** The "Recent computer science graduate with
   strong programming skills…" opener scores 1/5 — it could describe
   anyone. Replaced with a 2-line summary that names the specific
   degree, GPA, the kind of internship experience, and the role target.
   Specificity is the only thing that lets a recruiter sort.
2. **Education moved below Experience.** For a new grad with internship
   experience, Experience is the stronger signal; lead with it. For a
   candidate with no work history, Education stays first.
3. **Experience bullets rewritten with [CONFIRM] / [ADD IF TRUE].** The
   "before" had pure narration ("Worked on the backend", "Got positive
   feedback"). The "after" surfaces specifics where the user almost
   certainly has them (endpoint count, language, what the service did)
   and uses placeholders for the metrics. Did not invent N% test
   coverage or a latency number.
4. **Removed dead bullet** — "Got positive feedback from manager"
   describes how the candidate felt about the work, not what they did.
   It does not belong on a resume.
5. **Open-source contribution made concrete.** "Contributed to an
   open-source project" is a 1/5 bullet — every CS student could write
   it. Replaced with a structure that requires a real PR link and a
   one-line description of the contribution. If the user can't fill
   those in, the project should probably come off the resume.
6. **Capstone given scope.** "Team project for senior capstone" tells
   the recruiter nothing. The rewrite specifies team size, duration,
   stack, and the candidate's role.
7. **Skills section cleaned.** The "before" listed Kubernetes alongside
   Express — an internship-grade resume claiming production K8s
   experience is implausible. K8s was removed pending [CONFIRM]; AWS
   scope was flagged as [CONFIRM]. Cut Agile/Scrum (every team uses
   these; not a skill). Grouped by category.
8. **Tools that ARE skills surfaced** (pytest, Jest, GitHub Actions) —
   testing and CI are signals recruiters search for and new grads
   often have but forget to list.

## What the report would flag for the user

- **Questions** (workflow step 8): What was your AWS scope at Company
  A — did you deploy anything to production, or only touch dev/test
  environments? Did you write or modify the GitHub Actions workflow,
  or just use it? Approximate cohort size for the TA role?
- **Gap analysis** (software-engineering / backend domain): No
  visible exposure to caching, message queues, or observability tools.
  These are common new-grad gaps; not a blocker.

## What did **not** change

- Internship dates, employer names, school name — user-owned facts.
- The TA role stayed even though it has fewer bullets; teaching is
  positively viewed by many hiring managers and adds breadth.
